[V204.7 RC1] Conversation intelligence + natural action planning | 2026-09-27 | package 21.11.0-rc.1

- FEATURE: Added memory-only passive channel awareness. Ordinary human guild messages can populate a bounded guild+channel context window without any AI call, typing indicator, reaction, reply, mutation, or persistence. Default TTL is 30 minutes / 32 messages and operational channels are excluded by default.
- BEHAVIOR: Conversational speech is now explicit-mention-only across member AI, commissioner AI, and IT AI. Merely typing in #commissioner-ai or #it-ops and replying to the bot without @mention no longer authorizes AI speech. Slash commands/components/system workflows remain explicit event paths and are unchanged.
- FEATURE: Added deterministic natural action planner for commissioner team assignment. Requests such as `@myBot put Paul on the Ravens` resolve the member, team, and league, then reuse `openTeamsService.claimTeam()` instead of returning slash-command guidance.
- UX: Multiple leagues no longer force a league question when the requested team exists in exactly one league. If the same requested team exists in multiple leagues, myBot asks only which league and retains the rest of the plan for a short clarification window. Ambiguous member names request an @mention instead of guessing.
- UX: Explicit natural scoping such as `@myBot put Paul on the Ravens in Sunday League` is normalized into a clean team query plus league hint. The current explicit @mention message is excluded from ambient prompt rendering so the same request is not duplicated in model context.
- SAFETY: Passive context is labelled untrusted in AI prompts and cannot authorize an action. Natural mutations use current-message/pending explicit entities plus existing domain validation. No ambient conversation archive is written to JSON, PostgreSQL, Redis, or analytics.
- FALLBACK: If the deterministic planner does not recognize an intent, the request falls through to the existing commissioner AI/action-catalog path. If AI is down, supported deterministic team assignment still works. Process restart safely clears ambient and pending conversation state without touching durable league state.
- DOCS: Added docs/V204_7_CONVERSATION_INTELLIGENCE_RC1.md and expanded the comprehensive v204.7 implementation specification with conversation-awareness architecture, privacy boundaries, ambiguity logic, examples, failure matrix, test plan, and release gates.
- AFFECTED: index.js; src/handlers/commissionerHandler.js; src/handlers/memberMentionHandler.js; src/handlers/itHandler.js; src/services/ambientConversationService.js (new); src/services/naturalActionPlannerService.js (new); tests/conversationAwareness.test.js (new); .env.example; docs; package metadata.

Full `npm test` still cannot execute because the extracted dependency tree is incomplete (`MODULE_NOT_FOUND` from the shared test harness), and `npm run tsc` remains dependency-blocked; do not represent RC1 as production-certified until `npm ci && npm test && npm run tsc` pass in a dependency-complete environment.

WHY THE BOT STOPS RESPONDING ON RAILWAY (ROOT CAUSES + FIXES)

1. NO TIMEOUT — Anthropic SDK has a 10-minute default timeout. Railway silently kills
   functions after ~30-60 seconds, so the AI call gets dropped with no error logged.
   The bot shows "myBot is typing..." forever and never sends a reply.
   FIX: 22-second hard timeout via Promise.race in anthropicService.js. Any call
   that takes longer than 22s raises AI_TIMEOUT error, which sends "Took too long —
   try again." instead of silence.

2. RETRY STORM — 3 retries × 3s backoff = up to 9+ extra seconds added to already
   slow Railway cold-start calls. Combined with the timeout issue this guaranteed
   Railway function budget exceeded on any retry.
   FIX: Reduced to 2 retries, 1.5s backoff. Timeouts are NOT retried (retrying a
   timeout just doubles the wait for no benefit).

3. NO TYPING KEEPALIVE — Discord's "is typing..." indicator lasts 10 seconds.
   Railway AI calls can take 15-20s on cold start. Typing disappears before the
   reply arrives, so it looks like the bot gave up.
   FIX: sendTyping() called immediately at handler entry, then refreshed every 8s
   via setInterval until the reply is sent or the call fails.

4. CONCURRENT CALLS PER USER — User sends 5 rapid messages. Each one passes the
   3.5s cooldown check if sent fast enough. Railway tries to run 5 concurrent
   Anthropic API calls → rate limit → all 5 silently fail.

   released in all exit paths (replyAndRemember, gifUrl send, error catch).

5. LOCK NEVER RELEASED ON ERROR — If the AI call threw before reaching replyAndRemember,
